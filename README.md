# 🎓 Intelligent Student Performance Prediction System

A machine-learning web app that predicts whether a student is performing
**Excellent / Good / Average / Poor** from four academic indicators, explains
*why* it reached that conclusion, and generates a personalised improvement plan.

Built with **Python + scikit-learn (Decision Tree) + Streamlit**.

---

## 1. Objective

> Develop an AI system that predicts student performance based on academic
> information and suggests areas where the student needs improvement.

The project covers the full pipeline expected of a machine-learning mini
project:

| Stage | What was done |
|---|---|
| Data | 1,500-record synthetic student dataset with realistic correlations |
| Features | Attendance, assignment marks, internal marks, daily study hours |
| Model | `DecisionTreeClassifier` (gini, depth 6) |
| Evaluation | 80/20 hold-out split + 5-fold cross-validation + model comparison |
| Explainability | Decision-path extraction, feature importance, tree diagram |
| Output | Performance band, confidence, probability chart, ranked advice |

---

## 2. What the app does

1. **Takes student details** – name, roll number and four academic indicators.
2. **Predicts a band** – Excellent, Good, Average or Poor, with a confidence score.
3. **Explains the prediction** – the exact if/else rules from the tree that fired.
4. **Gives suggestions** – a prioritised action plan for the weakest indicators.
5. **Shows the model's credentials** – accuracy, confusion matrix, feature importance.

The UI has three tabs: **Predict**, **Model insights** and **Dataset**.
The sidebar contains one-click demo profiles (Excellent / Good / Average / At-risk)
so the system can be demonstrated in a viva in under ten seconds.

The front end uses a custom design system (`ui.py`): a gradient hero, pill tabs,
KPI tiles, an SVG readiness ring, CSS probability bars, styled tables and a
hand-built confusion-matrix grid. Any profile can also be opened directly with a
shareable link, which is handy during a presentation:

```text
http://localhost:8501/?demo=excellent
http://localhost:8501/?demo=good
http://localhost:8501/?demo=average
http://localhost:8501/?demo=risk
```

## 5. The dataset

`student_data.csv` is generated by `generate_dataset.py` using hidden
*ability* and *diligence* traits, so the four indicators are correlated the way
they are in a real cohort. Label noise (±2.5 points) keeps the classes
overlapping — otherwise the task would be too easy to be meaningful.

| Column | Meaning | Range |
|---|---|---|
| `student_id` | Anonymous ID | `STU0001…` |
| `attendance_pct` | Classes attended | 40 – 100 |
| `assignment_pct` | Average assignment score | 10 – 100 |
| `internal_pct` | Average internal exam score | 10 – 100 |
| `study_hours` | Self-study hours per day | 0 – 10 |
| `composite_score` | Weighted score used to create the label | 0 – 100 |
| `performance` | **Target label** | 4 classes |

**Label rule** (weights chosen to reflect how marks are usually distributed):

```
score = 0.20 × attendance
      + 0.25 × assignment
      + 0.35 × internal              + noise(σ = 2.5)
      + 0.20 × min(study_hours / 6, 1) × 100     (6 h/day = 100%)

Excellent ≥ 85   |   Good ≥ 70   |   Average ≥ 50   |   Poor < 50
```

**Attendance eligibility rule.** A student below **75% attendance** is normally
detained, so their band is capped at **Average** no matter how good the marks
are. This is a real institutional rule and it is what makes attendance a
meaningful feature instead of a passenger.

`composite_score` is **never** used as a model input — that would be data
leakage. It is only kept for reference and for the readiness gauge.

Class distribution: Excellent 219 (14.6%), Good 373 (24.9%),
Average 729 (48.6%), Poor 179 (11.9%).

## 7. How suggestions are generated

The predictor is a classifier — it does not produce advice by itself. Advice
comes from a transparent rule engine (`predictor.py`) that rates each indicator
against an academic benchmark and then ranks the gaps.

| Indicator | Excellent | Good | Needs attention | Critical |
|---|---|---|---|---|
| Attendance | ≥ 90% | ≥ 80% | 75 – 80% | < 75% |
| Assignments | ≥ 85% | ≥ 70% | 50 – 70% | < 50% |
| Internals | ≥ 85% | ≥ 70% | 50 – 70% | < 50% |
| Study hours | ≥ 5 h | ≥ 3.5 h | 2 – 3.5 h | < 2 h |

* Every indicator below "Good" produces one card with a diagnosis **and** a
  concrete action, sorted by how far it is from the recommended level.
* The predicted band adds band-specific advice (e.g. *"meet your faculty mentor
  this week"* for Poor, *"one band away — fix the two weakest inputs"* for Good).
* The top two gaps are surfaced separately as **"Start here"**.

This keeps the machine-learning part honest: the model classifies, the rule
engine advises, and both are explainable.

## 8. Viva questions (and short answers)

**What type of problem is this?**
Supervised learning → multi-class classification (4 discrete labels).

**Why a Decision Tree?**
Interpretability. The model can be printed as if/else rules, so a teacher can
verify a prediction by hand. It also needs no feature scaling and handles
non-linear boundaries.

**What is Gini impurity?**
The probability of misclassifying a randomly chosen sample in a node.
`Gini = 1 − Σ pᵢ²`. The tree picks the split that reduces it the most.

**Why limit `max_depth`?**
An unlimited tree memorises the training data (overfitting) and produces a huge,
unreadable diagram. Depth 6 with `min_samples_leaf=8` gave the best balance of
accuracy and interpretability in our experiments.

**Why does attendance matter so much in your model?**
Two reasons. It carries 20% of the composite score, and students below 75%
attendance are capped at Average because they are normally detained. Without
that eligibility rule the model happily called a 40%-attendance student
"Excellent", which no teacher would accept.

**Is the attendance cap cheating?**
No — it is domain knowledge encoded in the labels, exactly as a real college
would produce them. The model still has to *learn* the rule from data; nothing
is hard-coded in the classifier.

**Why accuracy is not enough?**
With four imbalanced classes, accuracy hides per-class errors. We also report
precision, recall, F1 and a confusion matrix.

**What is the confusion matrix telling us?**
Errors are almost always between neighbouring bands (Good ↔ Average). Distant
mistakes (Excellent ↔ Poor) never happen, which makes sense because the labels
come from a continuous score.

**What is overfitting and how did you check it?**
Memorising training data instead of learning the pattern. We compared test
accuracy with 5-fold cross-validation (86.3% vs 83.8%) and kept the gap small.

**Why 80/20 with stratification?**
80% is enough to learn from 1,200 rows; the 300 held-out rows give an unbiased
estimate. `stratify=y` keeps the class proportions identical in both sets, which
matters for the small Poor/Excellent classes.

**What is data leakage in this project?**
`composite_score` is derived from the four inputs and determines the label. If
it were used as a feature the model would appear ~100% accurate but would be
useless on real, unlabelled data.

**How would you use this in a real college?**
Feed attendance and marks from the ERP at the end of each internal cycle,
review flagged at-risk students with mentors, and retrain each semester on
verified final grades.

**What are the limitations?**
Synthetic data, only four features, no psychological/socio-economic factors,
labels derived from a formula rather than official results, and a small
accuracy gap versus ensemble models.

## 9. Limitations and future scope

* Replace the synthetic data with real (anonymised) institutional records.
* Add features: backlog history, previous semester GPA, family/economic context,
  participation, sleep and screen time.
* Try XGBoost / Random Forest and compare with SHAP explanations.
* Predict the **numeric** final percentage (regression) alongside the band.
* Add a login for teachers, multi-semester history and PDF report export.
* Detect drift by comparing each new batch of students with the training profile.
